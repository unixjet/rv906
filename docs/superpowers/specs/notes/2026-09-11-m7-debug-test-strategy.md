## 2. Test strategy in THIS project's harness (Verilator + C++, no OpenOCD)

Current state of the rv906 tree (the "revive" list): `rtl/CSR.v:1289-1304` zero-trigger stubs; `rtl/RTU.v:852,870-873,951,1129` — priority legs 1/4 tied 0, `halt_req_dm_async_tied0`, `rtu_yy_xx_dbgon=0` (the flush FSM's dead `IDLE->FE_BE` async-halt shortcut is already structurally present, `RTU.v:941-951,997`); `rtl/IDU.v:1173` — dret decodes illegal; `rtl/IFU.v:47-48` and `rtl/ICache.v:40-44` — dbg-mask/cache-diagnostic ports deferred to M7; `rtl/CSR.v` has no dcsr/dpc/dscratch constants at all.

**(a) Unit layer** — mirror `worktree test/m2/unit/Makefile` (one `--top-module` per bench, `obj/unit/<name>`, `bin/unit/<name>_tb`, aggregate `run` → `UNIT-SUITE-PASS`), as a new `test/m7/unit/` directory:

- **`dm_tb`** — Verilates the DM clone alone. The DMI boundary in the donor is an **APB slave port** (`tdt_dm.v:34-41`: `dm_paddr[11:0]/dm_pwrite/dm_psel/dm_penable/dm_pwdata → dm_prdata/dm_pready/dm_pslverr`) plus the core-side handshake (`tdt_dm.v:47-104`: `dm_core_halt_req_o/async/resume/halt_on_reset/itr/itr_vld/wr_vld/wr_flg/wdata` → `core_dm_halted_i/havereset_i/itr_done_i/retire_debug_expt_i/wr_ready/rx_data`). The cheapest scriptable protocol is a ~100-line C++ APB master (setup→access→wait pready) plus a "fake core" responder: on `halt_req`, assert `halted` after N cycles; on `itr_vld`, pulse `itr_done` after M; on `wr_vld/wr_flg`, update a shadow regfile and assert `wr_ready`; `rx_data` returns the shadow. This covers register defaults (the C906_DEBUG_PATTERN.v value table above), halt/resume handshake, abstract-command busy/cmderr paths (cmderr 1/3/4 per `tdt_dm.v:2041-2052`), haltsum0, dmactive/ndmreset — all without the core.
- **`dtm_tb`** — Verilates the TAP/DTM chain (`tdt_dtm_top` + `tdt_apb_master` clone) against a C++ fake APB slave. Drives `tck/trst_b/tms/tdi`, samples `tdo` after each `tck 1→0` eval. Walks Test-Logic-Reset (5× TMS=1) → IDLE → Shift-IR(5 bits) → Shift-DR; checks IDCODE==0x10000B6F, dtmcs abits==10/version==1/idle, and a 44-bit DMI scan (`{addr[9:0], data[31:0], op[1:0]}`, op LSB-first on the wire — `JTAG_DRV.vh:1103-1107`).
- **Core-side rows extend the existing benches** rather than new ones: trigger CSR readback/WARL rows in `test/m2/unit/csr_tb.cpp`; halt/resume/step/leg-1/leg-4 priority rows in `test/m2/unit/rtu_tb.cpp` (its header already documents legs 1/4 as structurally dead — `rtu_tb.cpp:29-34` — M7 makes them live and the bench must grow the corresponding input ports).

**(b) SoC layer** — extend the full-stack path: add JTAG pad inputs (`tck/tms/tdi/trst_b`, `tdo` out) to `RVProcAXI.v` (currently only `clk/rst_n`, `RVProcAXI.v:74-75`), and a C++ TAP driver in `RVProcTest.cpp` next to the existing `RVProcAXI_Verilator()` step loop (`RVProcTest.cpp:49-60`): functions `jtag_write_ir()`, `jtag_shift_dr(len, in, out)` (set TMS/TDI → eval → tck=1 eval → tck=0 eval → sample TDO), and a port of `ext_debug`'s `rwMemorybyDMIwithCheck` busy-poll — each DMI op consumes TCK cycles while `clk` keeps stepping so the CDC handshakes complete (a toggle sync never crosses if clk doesn't run — the driver must interleave N clk steps per TCK edge and never toggle clk and tck inside one `eval()`). A `--m7-debug` mode in the testbench main runs the fixed script against a loaded ELF and prints `M7-DEBUG-PASS/FAIL` markers; the acceptance script `test/m7/run_debug.sh` mirrors `test/m6/run_all.sh`/`run_linux.sh` (build → `timeout ... bin/verisim/testbench` → grep marker → exit code).

**The rv64mi-p-breakpoint interaction (read the source).** The test lives in the shared riscv-tests checkout (`/home/vlsilab/zhouz/workspace/C2RTL/rvproc/test/rv-test/riscv-tests/isa/rv64mi/breakpoint.S`, built as `test/m4/build/rv64mi-p-breakpoint.elf`; NOT vendored into the worktree — `test/m4/Makefile` compiles it in place from `RISCV_TESTS`). What it asserts, in order: (1) `csrs tcontrol, 8` must not trap (tcontrol exists); (2) `csrw tselect, x0; csrr a1, tselect; bne x0, a1, pass` — early-PASS if tselect reads nonzero; zero-trigger stub reads 0 so the test continues; (3) writes `tdata2 = &label1`, `tdata1 = (2<<60) | MCONTROL_M | MCONTROL_EXECUTE` and **requires exact readback equality** (`csrr a1, tdata1; bne a0, a1, 2f` skips to the next sub-test on mismatch) — today's stub reads 0 and every sub-test takes its skip branch, which is the M4 D-M4-5 pass mechanism (`rtl/CSR.v:1290-1298`); (4) with equality, `beqz x0, fail` at label 1 must **trap as cause 3 (breakpoint) BEFORE executing** (timing=0) — the handler (`:120-134`) checks `mcause==CAUSE_BREAKPOINT`, bumps `mepc+=4`, `mret`; (5) the same for M-mode LOAD and STORE matches, including "writes don't trap" negative checks; (6) `tselect=1` readback must be 1 for the second-trigger sub-tests (both triggers live simultaneously). Consequence for M7: once real triggers exist, the readback must be bit-exact for the supported field set (type=2, dmode, M, execute/load/store, timing=0, action=0, match=0), the trap must fire before execution via the pending-breakpoint priority leg (RTU leg 1), and tselect must select ≥2 real triggers or the test silently regresses to partial coverage. The M7 gate is "breakpoint passes through the REAL-trigger path", verified by checking the skip branches were NOT taken (e.g., via a directed variant that fails if any sub-test is skipped).

**OFF-path identity argument (case 6).** At reset: dmactive=0 (DM logic held reset, `halt_req/itr/wr_vld` idle), all trigger CSRs reset disabled (tcontrol.MTE=0), TAP sits in Test-Logic-Reset (tdo=1, no scans; the harness must hold TRST asserted or TMS=1 when not driving JTAG), and every new RTU/CSR/IFU input is tied to its current constant value. This is the exact shape of M6 Task 2's gate ("int_sel=0 at reset ⇒ bit-identical OFF path", `docs/superpowers/specs/2026-09-08-m6-interrupts-linux-design.md` task table). Gate: unit suite, sweep 86/87 (documented rv64ui-p-ma_data), atomics 19/19, m4 directed 30/30 + v suite 85/86, m5 46/46, m6 8/8, and the Linux boot banner — all unchanged after every M7 task, not just at the end.

## 3. SBA reachability

**rv906 slave map — verified** (`worktree rtl/RVProcAXI.v:152-159`): MEM `0x80000000`/2GB, CLINT `0x02000000`/64KB, PLIC `0x0C000000`/16MB, UART `0x10000000`/64KB; tohost = `0x7FFF_F000` (`rtl/rvproc_pkg.sv:35`, `ADDR_TOHOST` — inside the MEM aperture, routed by the LSU store path, `rtl/RVProc.v:1115-1124`). All are behind the internal AXI crossbar (2 masters I/D → 4 slaves, `RVProcAXI.v:236-238,757`), so a third master port sees the whole map.

**The APB-master premise is wrong — and that resolves the "decision point."** `tdt_apb_master.v` is **not** the SBA. Its ports (`gen_rtl/tdt/rtl/debug/tdt_apb_master.v:23-47`) are: TCK side `tck, trst_b, cmd_vld, addr[DTM_ADDR_WIDTH-1:0], wr_flg[1:0], wdata[31:0], dmihardreset → rdata[31:0], apb_wr_ready`; APB side `pclk, preset_b → psel, penable, pwrite, paddr[PADDR_WIDTH-1:0], pwdata[31:0] ← pready, prdata[31:0], pslverr`. It is the **DMI transport**: it carries the DTM's register accesses to the DM's APB slave (instantiated in `tdt_dmi.v:166-194`), internal to the debug unit, never touching the SoC fabric.

**`tdt_sba_axi.v` drives a genuine AXI4 master** (`gen_rtl/tdt/rtl/debug/tdt_sba_axi.v:36-67`): `awid[3:0], awaddr[AXI_ADDR_WIDTH-1:0], awlen[3:0], awsize[2:0], awvalid ← awready; wdata[TDT_DM_SBA_DW-1:0], wstrb[15:0], wlast, wvalid ← wready; ← bid[3:0], bresp[1:0], bvalid; bready; arid, araddr, arlen, arsize, arvalid ← arready; ← rid, rdata[127:0], rlast, rresp, rvalid; rready` — single-beat (awlen/arlen=0, `:235-236`), INCR burst, 128-bit data with lane-shifted wstrb for sub-128 accesses (`:158-216`), instantiated inside `tdt_dm.v:3214-3265` with `AXI_ADDR_WIDTH=SBAW=40`. So there is **no APB-vs-AXI bus mismatch**: the donor SBA is already an AXI master and matches rv906's AXI fabric. The real decision points are: (a) add it as **crossbar master #3** (`N_MASTERS 2→3`, `RVProcAXI.v:236`) with a **width adaptation 128→512** (`rtl/AXIWidthAdapter.v` already exists) or a narrow dedicated slave-side path — recommend the adapter through the existing crossbar so the same address decode serves; (b) address width 40 vs rv906's 64-bit `M_ADDR_WIDTH` (`RVProcAXI.v:237`) — zero-extend; (c) **the donor never validated SBA**: in the shipped SoC the entire SBA port is tied off (`smart_run/logical/common/tr_axi_interconnect.v:861-895`: `pad_tdt_dm_*` inputs tied 0, `tdt_dm_pad_*` outputs dangling), and C906_DEBUG_PATTERN does its memory access via program buffer, not sbcs (`C906_DEBUG_PATTERN.v:422-424`). SBA must therefore be gated against the debug-spec-0.13 text + our own crossbar, documented as a donor-untested surface.

## 5. Risk list (highest first)

1. **No runnable donor oracle for the whole subsystem.** The smart_run debug case cannot elaborate (filelist excludes RTL/tb, §1), and the donor SoC leaves SBA unwired (§3). Donor-as-spec still works (RTL is the spec), but there is no behavioral golden run. *Mitigation:* pin every register layout and FSM state to `file:line` in the extraction notes; port JTAG_DRV.vh's `ext_debug` semantics verbatim into the C++ driver (its poll/timeout constants and bit positions are the de-facto contract); gate SBA against the 0.13 spec text and record it as a donor-untested surface in the deviation ledger.
2. **DMI CDC in a two-clock C++ harness.** The DTM runs on TCK, the DM on the system clock, joined by toggle-handshake pulse syncs (`tdt_dmi_pulse_sync.v`). In Verilated comb-eval, a sync never completes unless `clk` steps between TCK edges; TDO is negedge-registered so it must be read after the `tck 1→0` eval; toggling clk and tck in one eval risks Verilator scheduling surprises. *Mitigation:* the C++ JTAG driver owns both clocks with a fixed interleave (e.g., 4-8 clk steps per TCK phase — the donor's own ratio TCK=clk/4 with idle=7, `tb.v:27-28` + `tdt_dmi_define.h:303-309`); land `dtm_tb` before any SoC JTAG test; simplify to pclk=clk (documented deviation, collapses two of the donor's three domains) so only the TCK crossing remains.
3. **Halt/resume vs. the M6-hardened RTU flush FSM.** Reviving legs 1/4 of the exception priority chain, `dbg_mode_on`, and the `IDLE->FE_BE` async-halt shortcut (`rtl/RTU.v:870-873,941-951,997,1129`) interacts with the interrupt epc/tval accuracy fixed in M6 Task 7 and the m6 8/8 suite; a halt racing an interrupt, or step-on-interrupt, is exactly where m6 regresses. *Mitigation:* extend `rtu_tb` with halt/resume/step/priority rows before any SoC work; re-run the m6 suite + full battery after every RTU-touching task; keep the async-halt shortcut dead until (and unless) async halt is actually implemented, mirroring the current dead-but-present clone discipline.
4. **Trigger match timing vs. the IFU/retire path.** rv64mi-p-breakpoint requires timing=0 (trap before execute) with exact tdata1 readback; the donor matches at the IFU execute-address stage (`aq_dtu_top.v:129-137`, `ifu_dtu_exe_addr0/1`) and raises the pending-breakpoint RTU leg, while load/store matches come from the LSU (`lsu_dtu_ldst_addr/data`, `aq_dtu_top.v:139-148`). rv906's IFU/LSU are different designs and have no dtu ports today. *Mitigation:* clone the shape — IFU-stage PC compare + LSU EX1 address compare feeding a new pending-halt input to RTU leg 1; add tdata1-hit suppression while `dbgon`; dedicated directed tests per match class (execute/load/store, M/S/U bits, second trigger) plus the readback-equality gate.
5. **SBA width/address adaptation into the 512-bit crossbar** (§3): 128-bit single-beat master into `M_DATA_WIDTH=512` (`RVProcAXI.v:238`) needs `AXIWidthAdapter` insertion and a new master index in the arbiter; errors here show up as silent wrong-lane data. *Mitigation:* SBA e2e reads a known pattern written by the test program first (byte-lane proof), then writes; keep `sbaccess=2` (32-bit) as the primary tested size (the donor's own default, `tdt_dm.v:2938`) with one 64-bit and one 128-bit row.
