# M1 IFU + ICache + BPU Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clone C906's front end (flat fetch pipeline, 32KB ICache, 3-structure
BPU: BHT+BTB+RAS) and prove it with the directed suite green at every rung of
the predictor chicken-bit ladder.

**Architecture:** Interface-first: freeze every module's port list in Task 1,
then build inside-out — ICache standalone, pipeline predictor-less,
harness+oracle, then predictors rung by rung. The committed-stream oracle
(FetchSink fake-BJU in RTL + C++ fetch-ISS) is predictor-agnostic, so the same
tests gate every rung. C906's ladder is shorter than C910's (rv12's own M1):
4 rungs, not 6 — there is no L0 BTB and no indirect BTB in this front end
(confirmed absent from the extraction notes' module list).

**Tech stack:** M0 scaffold (Verilator flow, `make verisim`, tohost protocol),
xpack GCC, restricted-SV recipe (umbrella spec §6).

**Normative documents (implementers MUST read the cited sections before coding):**
- Spec: `docs/superpowers/specs/2026-08-20-m1-ifu-design.md` (THE contract)
- C906 facts: `docs/superpowers/specs/notes/2026-08-20-c906-ifu-pipeline-extraction.md`
  and `notes/2026-08-20-c906-bpu-extraction.md` — copy behavior from the
  file:line spans cited there, not from memory. If a task needs a detail
  neither note resolved, read the cited RTL file directly
  (`refs/openc906/C906_RTL_FACTORY/gen_rtl/ifu/rtl/`) before guessing.

**Global contracts fixed by this plan (all oracles/tests must agree):**
- `JR_TARGET(pc) = (pc & ~64'h3F) + 64'h40 + (((pc >> 6) & 64'h3) << 6)`
  (a 64-byte-aligned pad 64..256 bytes ahead; pc is the BYTE address of the
  indirect jump). The .S generator places landing pads exactly there.
- Conditional direction rule: `taken = ^pc[7:4]` (byte-address bits).
- Shadow call stack: 16 entries (deeper than the real 4-entry RAS, but not
  absurdly so — see the RAS depth-limitation note below); push fall-through on
  committed pcall; pop = actual target on committed preturn; pop-on-empty
  returns the fall-through. Classification per C906's own predecode
  (confirm the exact rd/rs1 conditions from `idu/rtl/aq_idu_id_decd.v` or
  wherever C906 classifies pcall/preturn/ind_br — do not assume C910's exact
  register-set convention transfers unchanged; verify it during Task 5.1).
- **RAS depth-limitation contract** (design doc §2.1, §4.1): the real RAS is
  4 flop entries with pointer-only misprediction resync (no content resync).
  The ISS's 16-entry shadow stack must additionally implement a SEPARATE
  "RAS-faithful" prediction path used only for grading rung-2+ tests near
  depth 4 — read `aq_ifu_ras.v`'s pointer-resync logic in Task 7.1 and encode
  the SAME limitation in both FetchSink and the ISS, or the two oracles will
  agree with each other but not with the real BTB/RAS's shipped behavior.
- Harness config mechanism (pinned; owner = Task 5.2, consumer regs = Task 4.1):
  testbench CLI flags `--m1-rung=<1..4>` (ladder: 1=all predictors off,
  2=+RAS, 3=+BTB, 4=+BHT), `--max-insts=<N>` (default 200000), `--inv-test`,
  `--sink-stall`, parsed in `RVProcTest.cpp` (the M0 testbench uses custom
  `parse_arg`, NOT Verilator plusargs — same mechanism rv12 used). FetchSink
  hosts a config register bank (rung bits → the C906 predictor-enable wires,
  stall mode, max insts) exposed via `verisim.h`; the C++ side POKES it after
  `dut.init()` before the first step, and PULSES the invalidate bits mid-test
  for `--inv-test`. One owner, no ambiguity. (If a task discovers additional
  flags are needed, as rv12's did — `--fencei-patch`, `--iss-selftest`,
  `--no-checker` — add them and record it in the task's completion note,
  same precedent.)
- `verisim.h` M1 exports: per-cycle committed instruction (valid/pc/opcode
  from FetchSink registers — ONE slot, not three, since C906 delivers a
  single instruction/cycle to IDU), resolve/redirect event + kind, rung/
  config readback.
- Every task ends with: full-stack lint clean (`verilator --lint-only
  -Wno-fatal --top-module RVProcAXI rtl/rvproc_pkg.sv rtl/*.v`), build clean,
  commit with the Claude trailer. English only.
