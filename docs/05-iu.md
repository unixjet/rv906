# 5. The Integer Execute Units: IU

This chapter describes `rtl/IU.v`, the milestone-M2 integer execute unit. It
holds all four integer execution pipelines — ALU, BJU (branch/jump), MULT and
DIV — in one module (design doc S4.3 file-organization: no separate
`ALU.v`/`BJU.v`/`MULT.v`/`DIV.v`). It receives one dispatched instruction per
cycle from `IDU.v` (chapter 4) and produces results on four separate
write-back buses to `RTU.v` (chapter 6).

**How to read it.** Section 1 is the principle. Section 2 is this
implementation, unit by unit. Section 3 is the C906 cross-reference. Section 4
is the design discussion: deviations, bring-up bugs, and what stayed unbuilt.

**Normative documents.** The contract is
`docs/superpowers/specs/2026-08-20-m2-integer-design.md`; C906 facts in
`notes/2026-08-20-c906-iu-extraction.md`. Donor citations relative to
`refs/openc906/C906_RTL_FACTORY/gen_rtl/iu/rtl/`.

## 1. Principle: four pipelines, single issue

C906 issues one instruction per cycle into EX1, but the four integer
pipelines have different latencies:

- **ALU** — single-cycle, completes in EX1.
- **BJU** (branch/jump) — resolves in EX1; a conditional branch whose source
  is a still-pending load *parks* in a one-entry stall buffer instead of
  stalling the whole pipe.
- **MULT** — split multiply, several cycles; holds EX1 via `mult_issue_stall`.
- **DIV** — radix-4-style iterative divide, data-dependent length; holds EX1
  via `div_full`.

Because only one instruction occupies EX1 at a time, the multi-cycle units
backpressure the IDU (`mult_issue_stall`, `div_full`, `bju_full`) while they
work, and write their result back through a dedicated bus when done. A
conditional branch that would otherwise stall on a load instead parks in the
BJU's one entry and resolves when the load's data arrives by forward.

The PC-bookkeeping lives here too: `bju_pcgen_pc` tracks the PC of the
instruction currently in EX1 (advancing by 2 for RVC, 4 for 32-bit, on each
completion). AUIPC and the branch targets are computed from it.

## 2. This implementation

### 2.1 ALU

Single-cycle. `alu_active = idu_iu_ex1_alu_sel`; the result is computed
combinationally and written back the same cycle. Covers the RV64I ALU
opcodes (add/sub/and/or/xor/slt/sll/srl/sra and their *W/immediate forms,
lui/auipc). Sign/zero-extension for *W ops matches RV64 semantics.

### 2.2 BJU (branch/jump)

Resolves conditional branches (beq/bne/blt/bge/bltu/bgeu) and jumps
(jal/jalr) in EX1. Key pieces:

- **Private comparator** (IU note S4.1): the BJU compares operands with its
  own comparator, never the ALU's adder.
- **Parked-entry** (donor `aq_iu_bju.v`): a conditional branch whose source
  is a pending load (`bju_depend_lsu`) parks in a one-entry buffer and
  resolves when the load data arrives by forward (`da_xx_fwd_*` /
  `lsu_iu_ex2_*`). `bju_global_full` backpressures IDU while the entry is
  occupied.
- **Mispredict redirect** (`iu_ifu_tar_pc_vld`): fires when a conditional
  branch's actual outcome disagrees with the BHT prediction
  (`bju_cond_br_mispred`), or a JALR with `rs1 != x1` (a return the RAS
  should not have predicted), **or an unconditional jump** (Task 10, see §4
  bug #1). It flushes the front end and redirects `pcgen` to `bju_next_pc`.
- **`bju_pcgen_pc` tracker**: advances by 2/4 on each completion; redirected
  on mispredict/uncond. AUIPC and branch targets derive from it.

### 2.3 MULT

Split multiply (donor `aq_iu_mul.v`): a wide multiply computed over a small
FSM (`MUL_IDLE/SPLIT0/SPLIT1/CMPLT`), holding EX1 via `mult_issue_stall`
while it iterates, writing back through the EX3 bus when done.
`mult_issue_stall` is gated so the instruction retires at the final pass
(donor `aq_iu_mul.v:597`, see §4 bug #2).

### 2.4 DIV

Iterative divide (donor `aq_iu_div.v`): rv906 computes the *value* with a
Verilog `/`/`%` (clean-room) but models the donor's FSM states
(`DIV_IDLE/WFI2/ALIGN/ITER/CMPLT/WFWB`), the abnormal-result fast paths
(divide-by-zero, overflow), a one-entry memo buffer, and a data-dependent
iteration count (from the leading-one difference). Backpressures IDU via
`div_full`. The destination register is latched at dispatch (see §4 bug #3).

## 4. Design discussion: deviations, findings, and what stayed unbuilt

**Deliberate deviations (documented, design-doc-sanctioned):**

- **DIV value via Verilog `/`/`%`** (clean-room), with the donor's FSM
  *timing* (states, abnormal fast paths, data-dependent length) modeled. The
  result is bit-exact; only the datapath is simplified (IU note S6).
- **No RAS-target compare**: `ifu_iu_ex1_pc_pred` is absent, so the
  JALR-vs-RAS-target mispredict path is unbuilt; `iu_rtu_ex2_bju_ras_mispred`
  is tied 0. JALR-with-`rs1!=x1` still redirects.
- **No decode-time JAL-target correction**: BJU handles all redirects.

**Bugs found during M2 bring-up (fixed in this milestone):**

1. **Unconditional jumps must redirect the front end** (Task 10,
   `rv64ui-p-fence_i` + `rv64uc-p-rvc`). The donor relies on the BTB to have
   already redirected for a clean jump; with the predictors disabled (M2 pass
   bar, MHCR.btb/bht/ras=0) nothing redirected, so a `c.j`/`jal` fell through
   and the PC tracker drifted. Added `bju_uncond_redirect` to
   `bju_redirect_now` so every unconditional jump redirects.
2. **`mult_issue_stall` must be qualified with `MUL_IDLE`** (donor
   `aq_iu_mul.v:597`). A bare `iter_start` term stayed high for the whole
   split multiply, so the EX1 instruction never retired (`rv64um-p-mul`
   hang). Qualifying with `MUL_IDLE` lets it retire at the final pass.
3. **DIV must latch its destination register at dispatch.** The writeback
   happens many cycles after EX1 has moved on, so reading the live
   `idu_iu_ex1_dst0_reg` at completion wrote the result to the wrong
   register and left the real destination's WBT busy-bit armed forever
   (`rv64um-p-div*` hang). Fixed by latching `div_preg_reg` at dispatch.
4. **DIV FSM fast-path must not double-write.** The abnormal/hit fast path
   completes in `DIV_IDLE`; the FSM must not then also traverse the iterative
   path, or the result is written twice.

**Deliberately unbuilt in M2:** RAS (M2 pass bar disables it), vector/FP
execute, and the donor's full divide datapath (modeled, not bit-level).
