# M3b: Complete LSU — Non-blocking D-cache (LFB) + Prefetch (PFB) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans / superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Complete design-doc §7.4 M3 ("full LSU") — replace the blocking single-outstanding miss path with the C906's non-blocking Load-Fill-Buffer (LFB), add the RDL replacement engine, the VB victim buffer, and the PC-indexed stride prefetcher (PFB) with its MHINT CSR controls. Acceptance: rv64ua stays 19/19, full sweep stays 86/87 (only documented `ma_data`), unit suite green, plus new directed non-blocking tests.

**Architecture:** Faithful to the C906 structure (`refs/openc906/.../gen_rtl/lsu/rtl/`), adapted to rv906's existing single-outstanding ID-less 512-bit AXI and its PIPT 32KB/4-way/64B D-cache. The LFB provides non-blocking semantics (hit-under-miss, multi-miss tracking, replay-on-full); the physical bus serializes refills because the SoC memory/fabric is single-outstanding (documented adaptation — the donor's RID-based out-of-order bus would serialize here too).

**Tech Stack:** Verilog (rv906 FSM/structural style), Verilator, riscv-tests, unit benches.

## rv906 adaptation decisions (documented deviations)

1. **Bus serialization:** rv906 SoC AXI is single-outstanding, ID-less, single-port (`AXICrossbar` `mr_active`/`sr_active`, no `arid`/`rid`). The LFB issues ONE refill read at a time via its bus pointer; multiple misses are TRACKED in LFB entries but refills serialize. This is what the donor LFB would do on a single-outstanding bus. NO AXI-ID rework (protects green M2 base; no parallelism possible on single-port memory).
2. **512-bit single-beat refill:** rv906 moves a full 64B line in one beat (`arlen=0, arsize=6`), not the donor's 4×128b WRAP. Critical-word-first degenerates (whole line incl. critical word arrives at once) — the demand load is still satisfied directly from the refill beat.
3. **PIPT, no alias:** rv906 D-cache is PIPT (tag PA[39:13], index PA[12:6], single bank), unlike the donor's 2-bank virt-indexed aliasing scheme. So the VB's ALIAS read-back path and LFB alias-hit handling are unnecessary (rv906 `DCache.v` header already notes "no alias bank"). VB keeps only the dirty-victim writeback role.
4. **Reuse existing geometry/STB/AMO/LR-SC:** keep rv906's 32KB/4-way/64B arrays, the 4-entry STB + drain, and the M3-atomic AMO/LR/SC logic; the LFB integrates around them.

## Task A: LFB — non-blocking miss buffer (core)

**Files:** Modify `rtl/LSU.v`; the LFB may live inline in `LSU.v` (rv906 style) or as `rtl/LFB.v` instantiated by `LSU.v` — implementer's choice, prefer a separate `LFB.v` module for clarity given its size.

**Behavior:**
- 8 entries. Entry fields: line address {tag,index}, demand-vs-prefetch, load attributes (size, sign_ext, dst reg, byte_off/dw_off) for the demand load's writeback, WA-store flag + STB id, state.
- On load/AMO cacheable miss → allocate entry, capture the demand load's attributes; the LSU does NOT stall the front end (return to accepting ops). On write-allocate store miss → allocate LFB + create STB entry, STB entry waits the LFB.
- Refill engine: bus pointer scans entries round-robin, issues ONE AXI read (single outstanding), on the returning beat writes the line into the D-cache arrays (allocate victim way via replacement policy), then wakes/completes waiting ops.
- **Hit-under-miss:** a new load that HITS the cache completes normally while other entries are outstanding. A new load that misses to an IN-FLIGHT line waits/replays until that refill lands (donor replays; rv906 may stall-the-op or replay — match observable behavior).
- **Backpressure:** when all 8 entries busy, a new miss is not accepted (replay/stall). 
- Preserve STB-forward to loads (a load hitting a pending-storeed dword still forwards from STB).
- Keep uncached/SO loads/stores on the existing direct path (they do not allocate LFB entries).

**Step 1:** Write failing directed tests in `test/m2/unit/lsu_tb.cpp` (new T6+): (a) hit-under-miss — load A (miss), while A's refill is in flight load B (hit, different line) completes before A's refill returns; (b) two misses to distinct lines both eventually return correct data; (c) miss to an in-flight line returns correct data after the single refill; (d) LFB-full backpressure — 9 distinct-line misses, all eventually correct. Extend the lsu_tb AXI slave to add refill latency (multi-cycle) so overlap is observable.
**Step 2:** Run — confirm fail (current blocking LSU serializes / the bench may need the latency knob first).
**Step 3:** Implement LFB + integration. Replace blocking `ST_FRZ` for cacheable misses with LFB allocate + background refill; keep direct path for uncached/SO.
**Step 4:** Rebuild, run lsu_tb + full unit suite + rv64ua + full sweep; confirm green (86/87).
**Step 5:** Commit.

## Task B: RDL — replacement + dirty-victim engine

**Files:** `rtl/LSU.v` / `rtl/LFB.v` (and `rtl/VB.v` from Task C).

**Behavior:** Port the donor RDL responsibility: on an LFB refill that must evict a victim way, select the victim (replacement policy — keep rv906's prefer-invalid-then-round-robin, donor uses a FIFO; document), read out the victim's dirty line, hand it to the VB (Task C), then proceed with the refill. This decouples dirty-victim writeback from the refill critical path (vs the current inline MS_VPEEK/MS_VB_WRITE).

**Step 1:** Directed test: a miss that evicts a DIRTY line — the dirty data is written back AND the new line is refilled, and a subsequent load to the evicted (dirty) address returns the written-back value from memory.
**Step 2:** Implement RDL flow integrated with LFB refill.
**Step 3:** Rebuild + run lsu_tb, unit suite, rv64ua, sweep.
**Step 4:** Commit.

## Task C: VB — victim buffer

**Files:** `rtl/VB.v` (new) or inline; instantiated by `LSU.v`.

**Behavior:** Single-entry buffer holding a dirty evicted line; accepts it from RDL, then writes it back to AXI on its own schedule (decoupled from refill), freeing RDL to continue. (rv906 adaptation: no alias read-back path — PIPT.)

**Step 1:** Directed test: dirty-eviction writeback completes via VB while a subsequent refill proceeds; memory ends correct.
**Step 2:** Implement VB.
**Step 3:** Rebuild + run tests + sweep.
**Step 4:** Commit.

## Task D: PFB — PC-indexed stride prefetch + MHINT

**Files:** `rtl/PFB.v` (new) + `rtl/CSR.v` (add MHINT 0x7C5 with `dcache_pref_en` bit2, `dcache_pref_dist` [14:13]; route `cp0_lsu_dcache_pref_en/_dist` to LSU) + LSU integration.

**Behavior:** Port donor PFB: 4 PC-indexed entries + 1 global; trained by load MISSES; stride = new_load_PA − last_PA (<1KB); after confirmation (3 repeats PC / 15 global) prefetch addr+stride, advancing per grant, up to lookahead = stride×dist; pause when running ahead (SUSP); confidence/timeout eviction. Prefetch requests allocate LFB entries; demand always wins; suppressed if line already in LFB/STB/DC/VB. Gated by MHINT.pref_en (clearing it flushes PFB).

**Step 1:** Directed test in lsu_tb (drive a `pref_en` input): a striding load sequence causes prefetches that fill lines AHEAD of demand — verify by observing AXI reads to the prefetched lines and that a subsequent demand load to a prefetched line HITS. Also verify pref_en=0 disables prefetch.
**Step 2:** Implement PFB + MHINT CSR bits.
**Step 3:** Rebuild + run tests + sweep (prefetch must not break any existing test; default MHINT reset pref_en=0 keeps it off unless enabled).
**Step 4:** Commit.
