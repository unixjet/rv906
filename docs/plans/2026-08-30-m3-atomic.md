# M3: Atomic (LR/SC + AMO) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement RV64U atomic instructions (LR.W, SC.W, LWIR.AMDISF, all AMOs) in rv906 LSU.v as a faithful clone of C906's donor RTL.

**Architecture:** LR/SC uses a 1-entry load-buffer that tracks the last LR address+data; SC checks address match + no intervening store before committing the store. AMOs map directly to donor's `aq_lsu_amo` state machine with per-byte-enable forwarding and full-width WB at completion.

**Tech Stack:** Verilog (RTL), verilator simulator, riscv-tests amod* test suites, directed AMO benches in test/m2/unit/

**Key design decisions:**
- AMO width encoded in `func[3:2]` (matches `ag_size` for the read-phase
  access size): 10=W, 11=D. AMO funct5 in `func[8:4]`, AMO prefix `func[19:12]=0x01`.
- AMO writeback is cache-coherent: for a cacheable AMO the read-phase line is
  resident (hit or refilled miss), so the writeback STB entry is created with
  `was_hit=1` + latched way, and the drain updates that cache way. The test
  reads the NEW value back via a load through the DUT (cache hit), not golden
  memory (dirty line not yet written back).
- AMO ALU operand order follows donor: src0=memory/OLD, src1=register/rs1.
- W-width AMOs sign-extend the OLD value for the register writeback and the
  ex2 forward (the consumer condbr reads via the forward, not the GPR).
- SC.W result (sc_match_r) latched at ST_DCS; SC fails (returns 1) when no
  valid reservation (lr_valid_r=0), per RISC-V A spec.

**Remaining work:**
- Fix the rv64ua-p-lrsc SC-result writeback (see KNOWN ISSUE above).
- LR/SC stress tests (contention, interleaved reservations).
- 08-verification.md M3 acceptance note.

**Key implementation details:**
- `LSU_FUNC_LR=0x00b08`, `LSU_FUNC_SC=0x00b0c` — both have func[0]=0 so they're
  treated as load-like by the LSU's `ag_is_store = func[0]` check. This is a
  deliberate rv906 encoding choice (not the RISC-V funct7 layout) since rv906's
  IDU decodes into a 20-bit LSU_FUNC, and bit[0] is the store/load discriminator.
- LR/SC address latching uses `ag_addr` (VA) at issue_real for LR, and `dc_addr_r`
  at ST_DCS for SC. Both are compared as VA (identity-map MMU stub makes VA==PA).
- `lsu_rtu_lr_vld = cmplt_dp && lr_addr_set` (combinational, fires same cycle as
  wb_vld). `lsu_rtu_sc_res` = 0 on address match, 1 on mismatch.
- Testbench gotcha: for stores/SC, `src0=address, src1=offset, src2=data` — the
  LSU computes `ag_addr = src0 + src1`. Putting store data in src1 corrupts the
  address.

**AMO FSM design (for Task 5):**
The AMO read-modify-write sequence reuses the existing load path for the read
phase, then needs a write-back phase:
1. Detect AMO at issue_real, latch func + operands (src2 = register operand)
2. Read phase: route through ST_IDLE→ST_DCS→ST_FRZ/ST_REPLY like a load; the OLD
   value is `da_final` at ST_REPLY
3. Compute NEW = amo_alu_compute(src2, OLD, op, is_dw)
4. Write-back: create an STB entry with NEW value (like a store), so the updated
   data reaches memory; for cache-hits this merges into the array directly
5. Register writeback: OLD value to dst0_reg via lsu_rtu_wb_data/wb_vld
The challenge is that the current FSM completes a load at ST_REPLY with no
store-followup. The AMO write-back requires either a second pass through the
store path, or latching the computed NEW value and creating an STB entry in the
same ST_REPLY cycle.
